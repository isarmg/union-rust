# 00. 学习准备与第一次运行

本章目标不是立刻理解每行代码，而是先建立一个可观察、可重复的开发环境。运行成功后，再读源码会容易很多。

## 1. 先用一句话理解 UnionC

UnionC 是一个中心化管理系统：各台机器上的 Agent 定期读取本机资源指标，主动上报给 Linux Server；浏览器管理台再从 Server 读取当前状态与历史。Server 还可以代替浏览器访问若干 Sunshine 串流主机。

初学者最容易混淆三类“主机数据”：

| 页面或功能 | 数据来自哪里 | 是否持久化 |
|---|---|---|
| Server 本机资源总览 | Server 后台读取自己的 CPU、内存、磁盘、网络 | 前端仅保留短期内存曲线 |
| “主机”监控页 | 跨平台 Agent 上报 | SQLite 保存摘要历史与最新完整报告 |
| Sunshine 页 | Server 访问配置好的 Sunshine HTTPS API | 主机配置持久化，运行状态是后台快照 |

这三条链路彼此独立。没有 Sunshine，Agent 监控仍然成立；没有 Agent，Server 本机总览仍能显示。

## 2. 需要什么基础

你不必先成为 Rust 或 React 专家，但应会最基本的终端操作：

```bash
pwd                 # 我现在在哪个目录
ls                  # 当前目录有什么
cd web              # 进入 web 子目录
cd ..               # 回到上一级
```

推荐环境：

| 工具 | 要求 | 用途 |
|---|---|---|
| Linux | Server 只支持 Linux | 运行后端和完整工作区测试 |
| Rust stable | 当前 stable（workspace 未声明 MSRV；当前锁定依赖要求 1.95+） | 编译 Server、Agent、protocol |
| 系统原生构建工具 | C 编译器、linker 等；Debian/Ubuntu 可安装 `build-essential` | 编译内嵌 SQLite 等原生依赖 |
| Node.js | 24 或更高 | 编译前端 |
| npm | 10 或更高 | 安装前端依赖、运行脚本 |
| 浏览器 | 现代 Chromium、Firefox 或 Safari | 打开管理台 |
| curl | 可选 | 验证健康接口 |

检查版本：

```bash
rustc --version
cargo --version
node --version
npm --version
```

首次 `cargo` 和 `npm ci` 通常需要网络下载依赖；完全离线时必须事先准备好 Cargo 与 npm 缓存。不同 Linux 发行版的原生构建工具包名不同。

如果你在 Windows 或 macOS 上，只能直接开发 Agent 和 Web；完整 Server 开发应使用 Linux、WSL2 或 Linux 虚拟机。不要在非 Linux 上执行不带 `-p` 的整个 Cargo workspace 构建，因为它会尝试编译仅 Linux 的 Server。

## 3. 第一次构建

在仓库根目录执行：

```bash
cargo check --workspace
```

`cargo check` 会做类型检查但不生成最终可执行文件，通常比完整构建快。第一次执行需要编译依赖，耗时明显长于后续执行，这是正常现象。

再安装前端依赖：

```bash
cd web
npm ci
cd ..
```

`npm ci` 严格按照 `web/package-lock.json` 安装，适合可重复构建。不要用随意更新依赖版本的命令代替它。

## 4. 启动开发 Server

打开终端 A，位于仓库根目录。先创建一个只用于教程的临时目录：

```bash
export UNIONC_TUTORIAL_SERVER_DATA="$(mktemp -d /tmp/unionc-tutorial-server.XXXXXX)"
UNIONC_DATA_DIR="$UNIONC_TUTORIAL_SERVER_DATA" cargo run -p unionc
```

你应看到这些关键信息：

- 实际数据目录；
- 首次启动生成的管理员账号 `admin` 和一条随机密码；
- Server 监听 `127.0.0.1:8081`。

请暂时保存首次密码。它只在创建管理员配置时输出一次；忘记后需要通过离线命令重置。

另开一个终端验证健康接口：

```bash
curl http://127.0.0.1:8081/api/health
curl http://127.0.0.1:8081/api/ready
```

两者区别：

- liveness（`/api/health`）回答“进程是否活着”；
- readiness（`/api/ready`）回答“依赖是否就绪、现在能否接业务请求”。

## 5. 启动 Web 管理台

打开终端 B：

```bash
cd web
npm run dev
```

Vite 先尝试监听 `http://127.0.0.1:3001`，并把浏览器发往 `/api` 的请求代理到 `http://127.0.0.1:8081`。当 3001 已被占用时，当前配置没有启用 `strictPort`，Vite 会尝试 3002 等后续端口；始终以终端打印的 `Local` URL 为准。这样浏览器认为页面与 API 同源，前端代码可以使用 `/api/...` 相对路径。

在浏览器打开：

```text
http://127.0.0.1:<Vite 终端显示的实际端口>
```

使用终端 A 输出的 `admin` 和随机密码登录。登录后应看到：

- 顶部导航：总览、主机、Sunshine、日志、设置；
- 总览中的 Server 本机资源；
- 实时连接指示；若 SSE 暂时失败，页面会自动退回轮询。

## 6. 不联网运行一次 Agent 采集

回到仓库根目录，执行：

```bash
export UNIONC_TUTORIAL_AGENT_STATE="$(mktemp -d /tmp/unionc-tutorial-agent.XXXXXX)"
export UNIONC_AGENT_CONFIG="$UNIONC_TUTORIAL_AGENT_STATE/config.json"
export UNIONC_AGENT_STATE_DIR="$UNIONC_TUTORIAL_AGENT_STATE"
cargo run -p unionc-agent --bin unionc-agent -- probe
```

前三行确保教程不会读取已安装 Agent 的默认配置或状态。`probe` 本身只采集本机能力，不连接 Server，也不要求先配对。想看完整 JSON：

```bash
cargo run -p unionc-agent --bin unionc-agent -- probe --json
```

重点观察：

- `host`：稳定 ID、OS、架构、Agent 版本；Agent 不采集或上报设备名称；
- `system.cpu`、`memory`、`networks`、`disks`；
- `temperatures`、`gpus` 可能为空；
- `capabilities` 会解释某项为何可用或不可用；
- 缺失指标使用 `null` 或空集合，不使用数值 `0` 冒充采集成功。

`probe` 中的 `host.id` 只是这一次诊断临时生成的 UUID，每次执行都可能不同，也不会写入
状态目录。只有完成配对后，正常上报中的 `host.id` 才是 Server 分配的稳定实例 ID。

## 7. 可选：完成一次本地配对和上报

这一步继续复用第 6 节已导出的临时 Agent 配置与状态目录，不影响系统安装的 Agent。

### 7.1 管理台创建邀请

进入“主机”页，创建一个 Agent 实例，例如命名为“教程主机”。页面会显示一次性授权密钥。它默认 15 分钟后过期，且只显示这一次。

### 7.2 Agent 发起配对

继续使用第 6 节已导出 `UNIONC_AGENT_CONFIG` 和 `UNIONC_AGENT_STATE_DIR` 的同一个 Agent 终端。环境变量不会自动传给新终端；若必须换终端，先用第 6 节创建的那个精确临时目录重新导出三个变量。

```bash
cargo run -p unionc-agent --bin unionc-agent -- pair \
  --server http://127.0.0.1:8081
```

回环地址允许在开发环境使用 HTTP；非回环部署默认必须使用 HTTPS。

CLI 会打印激活路径。开发环境把 API 和页面分在两个端口，因此将打印 URL 的 `8081` 改为 Vite 终端显示的实际端口，路径保持不变。通常为：

```text
http://127.0.0.1:3001/agent/activate/<request-id>
```

若 Vite 实际使用 3002，这里也必须改成 3002。

打开该页面，核对设备摘要并输入管理台给出的一次性授权密钥。CLI 轮询到 `active` 后，会
通过 `Activating` 本地提交日志依次保存 token、host ID、配置和授权状态；每个文件单独原子
替换，最后才把配对状态写为 `Active`。这让中途崩溃可以幂等恢复，但不是一次覆盖多个文件的
单一原子事务。

### 7.3 上报一次

在同一个 Agent 终端中继续使用同一配置与状态目录：

```bash
cargo run -p unionc-agent --bin unionc-agent -- once
```

刷新管理台“主机”页，应看到“教程主机”的当前指标。也可以检查本地状态：

```bash
cargo run -p unionc-agent --bin unionc-agent -- status
```

## 8. 停止与清理观念

在运行进程的终端按 `Ctrl+C` 可优雅停止。教程数据保留在刚才由 `mktemp` 创建并打印的两个精确目录中。

不要把删除命令指向仓库根目录、用户主目录或生产目录。若之后要清理，应先打印并逐字确认变量值，只处理本次创建的精确 `/tmp/unionc-tutorial-...` 目录。

## 9. 常见首次运行问题

### 端口已被占用

Server 可临时换端口：

```bash
UNIONC_DATA_DIR="$UNIONC_TUTORIAL_SERVER_DATA" \
UNIONC_SERVER_PORT=18081 \
cargo run -p unionc
```

前端同时指定代理目标：

```bash
cd web
UNIONC_DEV_API_TARGET=http://127.0.0.1:18081 npm run dev
```

若只是 Vite 的 3001 被占用，它通常会自动选择后续端口；不要继续硬打开 3001，应复制终端实际打印的 URL。

### 页面能开，但无法登录

依次检查：Server 是否仍在运行、Vite 终端是否显示代理错误、是否使用了这次临时数据目录首次生成的密码。

### GPU 或温度显示不可用

这通常不是故障。平台、硬件、驱动和权限不同，Agent 会通过 capability 说明具体原因。先用 `probe --json` 看能力说明。

### 第一次编译很慢

Rust 与 npm 都要准备依赖缓存。只要终端仍有编译输出并且没有错误，继续等待即可；后续运行会快很多。
