# 02. 必要技术基础

本章只讲读懂 UnionC 必需的知识。目标是“看到代码知道它在表达什么”，不是完整教授 Rust、React 或数据库。

## 1. 先理解进程、库和协议

UnionC 开发时至少有三个独立进程：

- `unionc`：Server 进程，监听 HTTP；
- `unionc-agent`：Agent 进程，周期采样并发 HTTP；
- Vite 开发服务器：提供前端文件，并代理 `/api`。

`unionc-protocol` 不是进程。它是被 Server 与 Agent 编译进去的 Rust 库，定义双方一致的 JSON 数据结构。

HTTP/JSON 是进程间边界，Rust 函数调用是同一进程内的边界。不要把二者混为一谈。

## 2. Cargo 与 Rust 项目术语

| 术语 | 在本项目中的例子 | 含义 |
|---|---|---|
| workspace | 根 `Cargo.toml` | 一起管理多个 Rust 包 |
| package | `server`、`agent`、`protocol` | 一个 `Cargo.toml` 定义的发布/构建单元 |
| crate | `unionc`、`unionc_agent`、`unionc_protocol` | Rust 编译单元；名字在代码中用下划线 |
| binary target | `server/src/main.rs` | 可运行程序 |
| library target | `server/src/lib.rs` | 可被 binary 或测试复用的库 |
| module | `monitoring`、`auth` | 用 `mod` 组织的命名空间 |
| feature | Agent 的 `nvidia`、`otlp` | 编译时选择的可选能力 |

常见命令：

```bash
cargo check -p unionc
cargo test -p unionc-agent
cargo run -p unionc-agent --bin unionc-agent -- probe
```

`--bin unionc-agent` 用来从该 package 的 Agent、托盘和维护工具三个 binary target 中选出主 Agent；若省略，`cargo run` 会因无法确定要运行哪一个而报错。最后一个 `--` 表示后面的参数交给正在运行的程序，而不是交给 Cargo。

## 3. Rust 中最常见的类型

### 3.1 `struct`：一组有名字的字段

`protocol/src/report.rs` 中的 `AgentReport` 可以理解为一张严格表单；
`protocol/src/lib.rs` 负责将它重新导出给 Agent 和 Server：

```rust
pub struct AgentReport {
    pub schema_version: u16,
    pub report_id: String,
    pub host: HostIdentity,
    pub system: SystemSnapshot,
    // 省略其他字段
}
```

序列化为 JSON 后，字段名仍是 `schema_version`、`report_id` 等。

### 3.2 `enum`：有限状态集合

```rust
enum AgentCommand {
    Run,
    Once,
    Probe,
    Pair,
    Doctor,
    Status,
}
```

用 enum 表达状态比任意字符串更安全：编译器会要求代码考虑所有分支。

### 3.3 `Option<T>`：可能有，也可能没有

`Option<f64>` 只有两种情况：`Some(42.0)` 或 `None`。转为 JSON 时通常是 `42.0` 或 `null`。

这对监控很关键：

- `Some(0.0)`：成功采集，真实值为 0；
- `None`：没有采到，原因可能是硬件不存在、驱动缺失或权限不足。

### 3.4 `Result<T, E>`：成功或失败

异步函数常返回 `anyhow::Result<T>` 或项目定义的 `AppResult<T>`。`?` 的意思是：成功就取出值，失败就立即把错误向上传递。

```rust
let db = database::connect(&settings).await?;
```

这不是忽略错误，恰恰是在统一传播错误。

### 3.5 借用、所有权与 `clone`

- `String` 拥有一段可变长度文本；
- `&str` 借用文本视图；
- `&T` 借用值，不接管其生命周期；
- `.clone()` 创建可独立使用的值，或增加 `Arc` 引用计数。

`AppState` 在多个异步任务和请求间共享，因此内部大量使用 `Arc`。对 `AppState` 调用 `clone()` 通常只是克隆若干共享指针，不是复制整个数据库或全部主机数据。

## 4. Rust 异步与共享状态

### 4.1 `async` / `.await`

网络、定时器和数据库操作需要等待。异步任务等待时会让出线程，让同一个 Tokio runtime 处理别的请求。

```rust
let response = client.post(url).send().await?;
```

`.await` 只能在 `async fn` 或异步块中使用。

### 4.2 Tokio task

`tokio::spawn(...)` 启动并发任务。Server 用它启动资源采样、Sunshine 探测、内存回收和数据库保留期任务；Agent 用独立 worker 解耦采样和网络投递。

并发不代表可以忽略共享数据保护：

- `RwLock`：允许多个读者，写入时独占；
- `Mutex`：同一时间只允许一个持有者；
- `Semaphore`：限制并发数量；
- `watch`：保留最新值，适合状态快照；
- `broadcast`：一份事件发给多个订阅者；
- `Notify`：通知后台任务“现在应再运行一次”。

读注释时重点关注锁的范围。网络 `.await` 若发生在全局锁内，可能阻塞所有其他请求；本项目大量设计正是在避免这种情况。

## 5. Serde：Rust 与 JSON 之间的桥

常见派生：

```rust
#[derive(Serialize, Deserialize)]
#[serde(deny_unknown_fields)]
struct Example { /* ... */ }
```

- `Serialize`：Rust → JSON；
- `Deserialize`：JSON → Rust；
- `deny_unknown_fields`：出现未声明字段就拒绝，避免客户端悄悄使用过时或拼错的协议。

但“能反序列化”不等于“业务合法”。Server 还会在
`server/src/monitoring/model/mod.rs` 及其 `validation.rs` 子模块中检查 UUID 格式、
版本、长度、数值范围、集合大小和时间。

## 6. Axum：URL 如何进入 Rust 函数

典型路由：

```rust
Router::new().route("/api/monitoring/hosts", get(list_hosts))
```

handler 常使用提取器：

```rust
async fn handler(
    State(state): State<AppState>,
    Path(id): Path<String>,
    Query(query): Query<ListQuery>,
) -> AppResult<Json<ResponseType>> { /* ... */ }
```

| 提取器 | 数据来源 |
|---|---|
| `State` | Server 构造的共享应用状态 |
| `Path` | URL 路径变量，例如 `{host_id}` |
| `Query` | `?limit=20&offset=0` |
| `HeaderMap` | Cookie、Content-Type、认证头等 |
| `Json<T>` / `Bytes` | 请求体 |

handler 返回 `AppResult`。成功值转为 HTTP 响应，错误由 `server/src/error.rs` 映射为统一 JSON 和状态码。

## 7. 中间件是什么

中间件像一层层检查站：请求进入 handler 前做工作，响应离开 handler 后也能补充内容。

UnionC 的常见中间件负责：

- 生成可信请求 ID；
- 结构化访问日志；
- 添加安全响应头；
- 限制请求体；
- 校验管理员会话和 CSRF。

顺序很重要。安全头层需要包住业务路由和鉴权层，才能覆盖鉴权失败与业务错误响应；当前请求 ID 和 Trace 层还位于它外侧。Agent 路由使用自己的凭据，不能误套管理员 Cookie 会话。

## 8. SQLite 与 SQLx 基础

SQLite 把整个数据库保存在本机文件中，但它仍是关系数据库。

### 8.1 表、行、列和索引

```sql
CREATE TABLE monitored_hosts (...);
CREATE INDEX idx_monitored_hosts_last_seen_at
    ON monitored_hosts(last_seen_at DESC);
```

- 表保存同类记录；
- 主键唯一标识一行；
- 外键表达表之间的关系；
- `CHECK` 把一部分不变量下沉到存储层；
- 索引加速特定查询，但会增加写入成本。

### 8.2 事务

事务保证一组写操作要么全部提交，要么全部撤销。Agent 激活必须同时绑定邀请、配对请求、实例和 credential；只成功一半会产生无法恢复的身份状态，因此必须在同一事务中完成。

SQLite 允许多个读者，但同一时刻只有一个写事务。项目会缩短写锁范围、避免无变化 UPDATE、分批执行保留期删除。

### 8.3 SQLx

Server 通过 SQLx 连接 SQLite。常见形式：

```rust
query("SELECT ... WHERE host_id=?1")
    .bind(host_id)
    .fetch_optional(connection)
    .await?;
```

`.bind` 传参数，而不是拼接字符串，可以避免 SQL 注入并正确处理类型。

## 9. HTTP 必要知识

一个请求至少包含：方法、路径、请求头、可选请求体。

```http
POST /api/agent/v1/report
Authorization: Bearer <agent-secret>
Content-Type: application/json

{...AgentReport...}
```

常见状态码：

| 状态 | 在项目中的含义举例 |
|---|---|
| 200 | 查询成功或普通操作成功 |
| 201 | 创建邀请或 Sunshine 主机成功 |
| 202 | Agent 报告已接受或幂等确认 |
| 204 | 成功但没有响应体，例如注销、撤销 |
| 400 | JSON 内容不符合当前契约 |
| 401 | 管理员未登录或 Agent 凭据无效 |
| 403 | CSRF 失败、实例已撤销等 |
| 404 | 资源不存在 |
| 409 | 状态冲突或 ID 冲突 |
| 413 | 请求体过大 |
| 421 | 生产反向代理证明不符合契约 |
| 429 | 超过限流 |
| 500/503 | Server 或依赖暂时异常 |

方法也有语义：GET 读取，POST 创建或执行，PATCH 部分更新，DELETE 删除或取消。

## 10. TypeScript 基础

TypeScript 在 JavaScript 上增加静态类型。

```ts
interface MonitoringHostSummary {
  id: string;
  cpu_usage_percent: number | null;
  status: "online" | "stale" | "offline" | "revoked";
}
```

联合类型限制可用值；`number | null` 强迫调用者处理“没有采到”。类型只在编译期保护前端，
运行时服务器仍可能返回错误内容，所以 `shared/api/client.ts` 还会检查状态码和媒体类型。

常见语法：

- `const`：不可重新赋值的绑定；
- `?.`：对象可能为空时安全访问；
- `??`：左侧为 `null`/`undefined` 时使用默认值；
- `async`/`await`：等待 Promise；
- `map`：把数组每项转换为新值；
- `filter`：筛出满足条件的项；
- `import type`：只导入类型，不进入运行产物。

## 11. React 基础

### 11.1 组件

React 组件是返回 UI 描述的函数：

```tsx
function Greeting({ name }: { name: string }) {
  return <p>你好，{name}</p>;
}
```

JSX 看起来像 HTML，但其中 `{...}` 可以执行 JavaScript 表达式。

### 11.2 state 与 effect

- `useState`：保存影响界面的本地状态，例如当前视图、主题、输入框；
- `useEffect`：组件显示后建立外部连接或同步副作用，例如 SSE、localStorage；
- effect 返回的函数负责清理，例如关闭 EventSource 和定时器。

开发环境的 `StrictMode` 可能故意重复挂载/清理组件，帮助发现不完整的副作用清理。

### 11.3 React Query

React Query 管理“来自服务器的状态”：请求、缓存、新旧判断、刷新、错误和 loading。

```tsx
const query = useQuery({
  queryKey: queryKeys.services,
  queryFn: api.services,
});
```

`queryKey` 是缓存地址。写操作成功后通常用 `invalidateQueries` 让相关查询重新获取，而不是手工维护多份列表。

## 12. SSE 与轮询

普通 HTTP 是浏览器问、Server 回答。SSE 让 Server 在同一个长连接上持续向浏览器推送事件，适合单向状态更新。

UnionC 的前端先申请一次性短效 ticket，再建立 `/api/events?ticket=...`。连接断开时，页面不会停止更新：React Query 的普通轮询会接管。这叫“实时增强、轮询兜底”。

## 13. 测试基础

Rust 单元测试常放在同一文件的 `#[cfg(test)] mod tests` 中；集成测试放在 `server/tests`、`agent/tests`。前端使用 Vitest 与 Testing Library，文件名通常以 `.test.ts` 或 `.test.tsx` 结尾。

测试名应描述行为，例如“重复报告不刷新 last_seen”，而不是只写函数名。好的测试会在缺陷存在时必然失败。
